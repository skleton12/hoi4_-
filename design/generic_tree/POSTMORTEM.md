# 「기본 중점 변경 모드」 중단 회고

2026-10-12. 시험판 0.1.0 · 0.1.1 을 게임에서 켰을 때 **새 트리가 아니라 바닐라 기본 트리가 나왔고**,
사용자 판단으로 프로젝트를 중단했다. 다시 시작할 때를 위해 원인과 교훈을 남긴다.

## 증상과 확인된 사실

- 증상: 기본 트리 나라에서 바닐라 기본 중점이 그대로 보였다. (0.1.1 의 로딩 마커 `[GJ OK]` 결과와 `error.log` 는 받지 못했다.)
- 설계 데이터 448칸, `check.py` 오류 0.
- 모드 파일: `common/national_focus/generic.txt` (포커스 448개, `id = generic_focus`, `default = yes`),
  로컬라이제이션 1344키. `tools/validate.py` 오류 0 · 경고 0, 포커스 좌표 448개 모두 겹치지 않음.
- 지정 빌드 1.19.3.0 (GPT 가 `supported_version="1.19.3.*"` 로 맞춤).

**바닐라 트리가 "그대로" 보였다는 것 자체가 단서다.** 우리 `generic.txt` 가 읽혔다면 문법이 틀려도
바닐라 트리는 사라졌어야 한다(같은 경로 파일은 통째로 대체된다). 즉 우리 파일이 **아예 적용되지 않았다.**
검사기로 잡을 수 있는 "내용" 문제가 아니라 "적용" 문제다.

**GPT 확인 (사용자 PC 로그):** 게임 로그상 **로드된 모드가 0개**다. 중점 문법 오류가 아니라 모드 자체가 읽히지 않았다.
따라서 직접 원인은 **1·2(·5) 쪽**이고, 3·4 는 모드가 로드된 다음에야 따질 문제라 지금은 배제한다.
"작은 모드부터 확인했어야 한다"는 과정의 문제이고, 이번 실패의 직접 원인은 아니다.

1~2 는 마커 한 번으로 갈린다: 마커가 **안 보이면** 1·2·5, **보이는데 바닐라 트리면** 3·4 다.

## 과정에서의 원인

1. **"뜨는지부터 확인" 원칙을 지키지 않았다.** 처음 계획은 "뼈대 40칸 → 게임에서 확인 → 확장"이었다.
   실제로는 설계를 720 → 331 → 448칸까지 다듬은 뒤에야 첫 시험판을 만들었다. 덮어쓰기가 되는지는
   포커스 1칸짜리 모드로 하루 만에 알 수 있었던 일이다.
2. **게임 파일과 로그에 접근할 수 없었다.** 작업은 클라우드 컨테이너에서 했고, 검증은 우리가 만든 파서뿐이었다.
   결정적인 가정(바닐라 파일 이름·트리 id·덮어쓰기 동작)을 실제 1.19.3 설치본에서 확인하지 못했다.
3. **실패 신호가 짧았다.** "기본 중점 나옴" / "실패함" 만으로는 원인 1~5 를 가를 수 없다.
   마커는 0.1.1 에서야 넣었고, 그 결과를 받기 전에 중단됐다.
4. **설계 쪽 소모가 컸다.** 틀을 세 번 바꿨고(긴 사슬 → 넓고 얕게 → 정치 확장), 두 AI 가 같은 파일을
   번갈아 고치며 재작업이 생겼다. 이 시간에 적용 시험을 먼저 했어야 했다.
5. 로드되더라도 **효과는 대부분 안내 문구**였다(실제 효과는 정치력·공장·안정도 등 일부). 한글 글꼴 모드도 따로 필요했다.

## 다시 시작한다면

1. **연기 시험(smoke test) 먼저.** `generic.txt` 에 포커스 1칸(`id = generic_focus`, `default = yes`)만 넣은 모드를 만든다.
   이름은 ASCII 로(`GJ TEST`) 해서 글꼴과 무관하게 보이게 한다.
2. 사용자 PC 에서 세 가지를 받는다: ① 국가 선택 화면 마커, ② 런처 플레이세트 화면, ③ `error.log`.
3. 게임 폴더에서 바닐라 기본 트리의 실제 파일 이름과 `id` 를 확인한다
   (`Hearts of Iron IV\common\national_focus\` 에서 `default = yes` 검색).
4. 1칸 트리가 바닐라를 대체하는 것을 확인한 뒤에만 `build_mod.py` 로 448칸을 올린다.
5. 가능하면 사용자 PC 에서 Claude Code 를 돌려 `error.log` 와 게임 파일을 직접 보게 한다.

## 다음 시험: 런처 실행 vs `hoi4.exe` 직접 실행 (GPT 제안)

현재 확인된 것은 **로딩 단계 실패(모드 0개)** 까지다. 정확한 원인은 아직 확정하지 않았다.

- 두 실행 모두 **같은 사용자 폴더·같은 `dlc_load.json`** 에서 한다. 직접 실행 전에 `enabled_mods` 에
  `"mod/gibon_jungjeom.mod"` 가 들어 있는지 확인하고, 런처를 거친 뒤에는 런처가 그 파일을 다시 썼는지 비교한다.
- 직접 실행이 런처나 스팀으로 되돌아가면 그 실행은 비교에서 뺀다.

| 런처 실행 | 직접 실행 | 좁혀지는 곳 |
|---|---|---|
| 0개 | 로드됨 | **런처**: 플레이세트가 비었거나 다른 플레이세트가 활성, 실행 때 `dlc_load.json` 을 덮어씀, 버전 호환 판정 |
| 0개 | 0개 | **런처 밖**: 게임이 읽는 사용자 폴더(OneDrive), `.mod` 파일 위치·`path`, `dlc_load.json` 자체 |
